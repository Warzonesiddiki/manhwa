# 21 — Owner's production workflow (future user guide)

**Status:** target operating procedure, not a claim the current app supports it.

## Before starting

Have an authorized original source file, its YouTube reference if relevant, rights/attribution details, a rough budget, and a plan for Urdu review. If music must be preserved, obtain a separate licensed stem; the mixed English voice/music track cannot simply be treated as clean background.

## 1. Register and inspect the source

Paste the link, name the project, record source rights, and upload the file. Wait for real inspection. Verify duration, video identity, sound, and a beginning/middle/end preview before spending on transcription. For an unavailable link, supply the source file; do not accept an unrelated sample as a replacement.

## 2. Get and review the transcript

Import matching SRT/VTT or run source-audio transcription. Check uncertain spans, names, numbers, dialogue changes, and chunk boundaries. Correct transcription before translation. Verify subtitle timestamps align with the source and have not shifted after an intro or cut.

## 3. Plan episodes and glossary

Choose publishable episode boundaries; keep a separate source-global timeline. Establish character names, ranks, attack names, places, preferred Urdu/Roman spellings, and pronunciations. Approve glossary changes deliberately so voices remain consistent across the marathon.

## 4. Adapt and approve Urdu

Read English and Urdu side by side. Roman Urdu is a reading aid and should agree with the Urdu script. Prefer clear conversational narration over repeated generic hooks. Flag changed meaning, missing negation/numbers, invented scenes, and lines too long for their time windows. Save and approve revisions.

## 5. Approve a voice pilot

Generate 60–120 seconds covering ordinary narration, drama, difficult names, and numbers. Listen on headphones and ordinary speakers. Approve intelligibility, naturalness, pacing, consistency, and pronunciation. If settings change, approve a new pilot before generating hours of clips.

## 6. Run the resumable batch

Review estimate and project cap, start generation, and monitor committed counts rather than an animated percentage. You can close the browser after the job is durably accepted. Failed steps remain failed; retry them after checking reason/cost. Pause or cancel if quality/budget is wrong; already submitted provider work may still be billed.

## 7. Resolve timing and quality

Review overflow, missing audio, silence, clipping, pronunciation, and uncertain content flags. Shorten faithfully and regenerate where necessary. Do not fix long lines by cutting off words. Review episode joins and a reproducible sample of unflagged clips.

## 8. Export and verify

Select an episode or destination-valid publication package, correct revision and source range, caption mode, and audio mix. Request a full archival master separately if needed. Wait for final QA. Check the downloaded file itself: beginning/middle/end, episode joins, duration, Urdu audio, captions, and required attribution. An editor preview is not sufficient evidence that the MP4 is correct.

## 9. Archive and clean up

Download/retain the versioned manifest and required media, verify checksums where provided, and follow the retention policy. Test a restore on an early project. Delete source/provider copies only after you understand what can no longer be regenerated.

## What to do when something fails

- Wrong narration after an edit: check stale revision/cache status; regenerate affected line, not all clips.
- No source video: attach authorized media; URL understanding alone is not export input.
- Quota/budget exceeded: wait or approve a revised limit; do not repeatedly click generate.
- Unnatural Urdu: improve glossary/script/profile and pilot before resuming.
- Wrong export duration/source: stop release and inspect manifest; do not publish a “mostly correct” file.

Publication is manual in v1. The tool assists localization; the owner still decides whether the final work is accurate, licensed, and suitable for their channel.

## Day-long additions

Expect uploads and processing/review to span days depending on bitrate, uplink, quotas and review time. Keep the browser open for a local-file upload; after durable server-job acceptance, browser closure does not stop those jobs. Reopen/reselect/resume uploads according to the actual session state.

For 24-hour sources, review in saved sessions and approve each chosen range. Final publication normally uses valid episodes/parts with local captions/chapters; an optional full archival master is a different output. See docs 23–28 for limits, time estimates, coverage and the destination policy. Check actual downloaded parts, not only an app progress banner.
